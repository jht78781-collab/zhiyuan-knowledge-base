# 知源三分钟演示与验收

用一组虚构的差旅制度，展示员工如何查到答案、打开对应原文，以及系统如何限制不同用户访问的资料。完成真实 Dify 验收后，这套流程可用于面试演示或录制短视频。

## 演示前准备

- 创建「财务差旅」和「研发测试环境」两个知识库。财务库上传 `materials/finance` 的三份文件，研发库上传 `materials/engineering` 的文件。通过知源上传，等待文件状态变为「可用」，以便系统将引用对应到本地原件。
- 用管理员准备一个普通账号，只给它「财务差旅」的查看与提问权限。浏览器普通窗口登录普通账号，另一个窗口保留管理员页面。事先复制研发文档的下载地址，供权限测试。
- 现场演示用已经索引好的文件。在开始前各试一次 PDF 引用、续问和下载，并把问答停在一个空白会话。

## 三分钟走屏顺序

| 时间 | 画面和操作 | 可以这样讲 |
|---|---|---|
| 0:00–0:20 | 打开普通员工的知识库列表 | “这是我做的企业知识库个人实战项目。员工登录后可以向已授权的资料提问，并回到原文核对答案。” |
| 0:20–1:20 | 在财务库问“普通城市住宿每晚上限是多少？”，展开引用并打开 PDF。继续问“那高铁能坐什么等级？” | “标准是 350 元一晚。引用指向实际的费用标准。下一问在同一个会话里，能接着查到高铁二等座。” |
| 1:20–2:00 | 问“今年年终奖什么时候发？”，展示资料不足。切换到普通账号的知识库列表，并打开预先复制的研发文档地址 | “库里没有奖金规定，系统会提示资料不足。普通账号只看得到财务库，直接访问研发文档也会被后端拒绝。” |
| 2:00–3:00 | 切到管理员，展示三种文件的索引状态和用量页 | “Java 负责登录、权限、文件状态和历史，MinIO 保存原件，Dify 负责解析、检索和生成。耗时由 Java 测量，Token 只记录 Dify 返回的值。” |

## 把模拟联调替换为真实 Dify

1. 使用自己的 Dify Cloud 或已部署的 Dify。确认模型供应商和嵌入模型可用。在 Dify 创建两个**经典知识库**，记下各自的 Dataset ID。[Dify 知识库 API](https://docs.dify.ai/en/api-reference/guides/knowledge-base-api)
2. 为两个知识库分别建立 Chatflow。每个流程只选择自己的 Dataset。建议从「用户输入 → 知识检索 → LLM → 直接回复」开始。在 LLM 的 **Context（上下文）** 选检索节点的 `result`，让提示词明确要求依据资料作答。开启 **Citations and Attributions（引用与归属）**，以及 LLM 的 **Memory（记忆）**。如果省略主语的追问检索不到资料，在检索前加一个启用记忆的问题改写节点，将追问改为独立的检索问题。[知识检索节点](https://docs.dify.ai/en/cloud/use-dify/nodes/knowledge-retrieval) · [LLM 节点](https://docs.dify.ai/en/cloud/use-dify/nodes/llm) · [引用设置](https://docs.dify.ai/en/cloud/use-dify/build/additional-features#citations-and-attributions)
3. 发布两个 Chatflow，在各自应用里创建应用 API 密钥。再从 Dify 的知识库 Service API 创建知识库 API 密钥。把配置填入项目本机的 `.env`，不要复制到聊天、源码或视频里。[Dify 应用 API 入门](https://docs.dify.ai/en/api-reference/guides/get-started)

   ```dotenv
   DIFY_BASE_URL=https://api.dify.ai/v1
   DIFY_KNOWLEDGE_KEY=<你的知识库 API 密钥>
   DIFY_CHAT_KEYS={"finance":"<财务 Chatflow 密钥>","engineering":"<研发 Chatflow 密钥>"}
   ```

   自托管时，`DIFY_BASE_URL` 改成你的 Service API 地址并保留 `/v1`。重启后，在知源分别用 `finance`、`engineering` 和对应的 Dataset ID 新建知识库。请参照项目 README 配好 MariaDB 和 MinIO。

## 录屏前逐项检查

| 检查问题或动作 | 通过条件 |
|---|---|
| 普通城市住宿每晚上限是多少？ | 350 元一晚，能打开 PDF《国内差旅费用标准》并核对。 |
| 紧接上一轮问“那高铁能坐什么等级？” | 答到高铁或动车二等座，历史保留两轮。 |
| 出差结束后几天内提交报销？审核多久？ | 提交期限 5 个工作日，完整材料的审核时间通常为 3 个工作日。引用 TXT《差旅报销提交规则》。 |
| 需要提交什么材料？ | 已批准的出差审批单、有效发票、付款凭证、行程凭证。引用 DOCX《差旅报销材料清单》。 |
| 今年年终奖什么时候发？ | 提示资料不足，没有把不相关的差旅资料当成答案。必要时在 Dify 调整检索分数阈值及无命中分支，再试一次。 |
| 用财务成员打开研发文档链接。 | 页面无研发库，下载请求被拒绝。切换到研发库管理员可找到样例标识 `DEMO-RD-742`，用于对比。 |
| 打开管理后台的用量页。 | 有实际调用次数和响应时间。若 Dify 没返回某项 Token，对应值保持为空。 |

录屏建议保留三个镜头：答案与原文、普通账号被拒绝访问研发资料、管理员看索引和统计。对外发两到三分钟的录屏加源码说明即可。若对方需要亲自试用，再准备独立的只读演示账号和线上环境。

目前的本地预演使用虚构资料和 Dify 接口模拟服务。上表是接入真实 Dify 后的通过标准，模拟回答和用量不可作为真实检索效果或性能数据。
