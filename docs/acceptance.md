# 第一版验收步骤

本项目的 Maven 测试覆盖 Dify 的聊天事件、引用和用量解析。部署时再用实际 Dify 实例验证模型和解析结果。

1. 创建全新的 MariaDB 10.5 数据库并启动应用，检查 Flyway V1–V3 成功。输入带有中文和 emoji 的知识库名称，刷新后检查原样显示。另建空库将 `APP_MIGRATIONS` 指向空目录，确认应用仍可启动。
2. 准备两个不同 Dataset 和两个独立 Chatflow。财务资料写入“报销审核需要三个工作日”，研发资料写入独有测试词。给普通成员只授权财务知识库，核对研发知识库、原文及会话无法访问。
3. 分别上传带文字的 PDF、DOCX、UTF-8 TXT。检查从保存、索引到可用的状态。下载原件并核对内容。上传无有效 PDF 文件头的假 PDF，确认被拒绝。
4. 在财务知识库提问“报销审核需要多久？”，查看可下载的引用文件。追问“提交时需要哪些凭证？”，退出后重新登录，确认两轮记录可见。问与资料无关的问题，确认没有可核对的来源时显示资料不足。
5. 查看用量页。在选择同一天时，确认成功、失败和耗时统计与实际调用一致，实际返回的 Token 单独汇总。使用实际 Chatflow 检查是否带有输入、输出或总 Token。
6. 删除引用所对应的文档，确认无法再下载，历史不再显示该片段。撤销用户对财务知识库的权限，确认旧会话无法读取。停用用户，确认已登录会话失效。
7. 使用隔离的 Dify 或 MinIO 测试环境验收失败与重试。检查清理或索引失败时能查看原因、修复配置并重试。
